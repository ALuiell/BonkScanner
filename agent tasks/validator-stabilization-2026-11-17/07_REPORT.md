## 2. Exact end-to-end ownership and durability boundaries

1. **Privileged worker → local IPC.** `Validator/src/bonkscanner_validator/worker.py:326-379` requires elevation, authenticates its parent and pipe, and emits events tagged by run ID. Its `_CreditSlot` reserves bounded FIFO bytes and keeps a single event credited until the parent ACK (`:182-235`). Non-diagnostic FIFO overflow emits terminal `kind=loss`, not fabricated intact evidence (`:235-292`). Diagnostic `security_audit`/`process_access` updates have separate budgets; individual updates may be skipped under pressure and counts tracked (`:239-299`). `WorkerClient.poll:99-131` receives an event, sends the IPC ACK and returns it for Controller handling; `ipc.py` uses size-bounded sequenced frames. **Important trust boundary:** this IPC ACK is not the subsequent *server* ACK. Crash after local IPC credit but before server persistence cannot be repaired from the worker.

2. **Controller / overlapping attempts.** `Validator/controller.py:145-205` maps each `run_start`, `payload`, `run_end` to the exact `localRunId`, retaining previous unfinished runs in `_tracked_runs`; only the current run updates live UI state. An old terminal event arriving after the next start is delivered to its original transport session, not silently assigned to the new attempt. On observer failure, orphaned runs close with no certified terminal evidence (`:280-324`). `tests/test_deferred_controller_delivery.py:28-75` explicitly encodes old-end-after-new-start, old payload not replacing current UI, worker failure, duplicate terminal suppression. Agent 04 owns physical lifecycle/IPC shutdown verification.

3. **Local v3 buffering and network.** `Validator/transport.py:126-200` creates a local per-run session, negotiates six optional v3 features, caps unfinished sessions at 32 and stores bearer tokens plus immutable pending requests **only in RAM**. `protocol.py:958-962` defines max request 262,144 UTF-8 bytes, 15 MiB managed buffer and 4 KiB reserved loss accounting per session. `buffer.py:16-56` and `transport.py:58-75,335-383` enforce contiguous intervals, carry metadata-first split fragments and, on overflow/framing pressure, emit explicit `queue_loss` all-channel gaps rather than silently claiming complete coverage. A rejected final payload or queue loss removes `confirmedRunEndMs` (`transport.py:217-253,345-355`). Finish attaches terminal offset, Direct-Open completion and optional image/Security/correlation summaries after prior fragments are queued (`:384-434`). A summary may be downgraded/dropped when oversized or invalid; `diagnostic_summaries_dropped` exposes that limitation (`:405-433`). This is a **quality limitation**, not a server receipt of the omitted evidence.

4. **Server enrollment → authenticated sequence → PostgreSQL.** `Server/sessions/enrollment.py:50-77` allocates a UUID session, a secret write token (only its digest is persisted), fixed accepted feature subset and pinned rule versions. `sessions/models.py:6-24` stores binding, accepted features, compact evidence, `last_seq`, last operation, canonical request digest, serialized `last_ack`, timestamps/deadlines and availability in PostgreSQL. `sessions/delivery.py:37-58` hashes RFC8785-canonical `operation + request`; `:118-142` locks the session row with `SELECT FOR UPDATE` inside `transaction.atomic`. `:71-115` validates and applies the payload before committing its evidence, ACK and sequence together. An **identical** retry with the same sequence/operation/digest gets exactly the saved ACK without reapplying evidence or moving freshness; a conflicting same-sequence request returns 409; gaps or stale sequences are rejected. Invalid mutations do not consume the next sequence. PostgreSQL transactionality supports an acknowledged write **after commit**, not immunity to client loss *before* commitment.

5. **Lost HTTP ACK / retried finish.** `Validator/transport.py:477-537` does not advance sequence, release the in-flight buffer or mark completion until the matching `sessionId` + `lastSeq` + valid ACK is received. On timeout/503/429 it retries the same in-memory request with backoff (`:565-601`), permitting the server's exact saved ACK replay after a lost response. A 400 optional correlation mismatch has a single explicit client-side replacement path: remove only optional `accessCorrelations` before retrying the still-unconsumed sequence, record diagnostics as dropped (`:538-557`). Other 400/401/403/404/409/410/413 are terminal for that attempt. **Process exit or crash loses this in-memory retry ability**; there is no disk write-ahead queue nor durable client write-token, so do not promise replay following a *client* restart. Current `scripts/check_local_durability.py:43-67` instead tests *server/database* restart while an external script retains the request and token.

6. **Expiry, stale and publication.** `Server/sessions/lifecycle.py:11-26` uses 30 seconds to mark stale, 900 seconds for inactivity, 90 days for public qualifying closed reports and 900 seconds for *provisional* last-ACK replay after closure. `:46-65` calls a session `completed` only if the accepted final payload has non-null `confirmedRunEndMs`; otherwise `interrupted` (including server inactivity). `sessions/delivery.py:61-68,96-115` first publishes at 15,000 ms accepted observation (subtract union of all-channel gaps) **or** a genuine classified v4 finding; `available` is monotonic per session. Provisional closures discard identifying binding and evidence but retain enough last-ACK data to satisfy exact retries (`lifecycle.py:18-26`). The recurring sweep uses DB row locking and time-based gates (`:83-105`), and reads still hide expired reports even before cleanup (`reports.py:22-35`). `Validator/transport.py:565-593` can, on definitive 410 during an active attempt, start a **new** `attached_mid_run` session with a new local run identity, deliberately losing full-start certification; it does not splice sessions into one clean audit.

7. **Pinned classification and presentation.** `Server/sessions/rules.py:5-39` retains registry v1–v5 (current 5), catalogue v1–v4 (current 4), assessment v4, and the pinned MegaBonk 1.0.69 / 13-file reference. `classification.py:559-581` retains assessment v1, v2, v3 and v4 dispatch. The report is derived from **persisted, version-pinned evidence**, not reclassified with a subsequently updated catalogue (`reports.py:87-128`). `reports.py:131-170` constructs a detailed **private** projection for operator export; only `public_summary` enters GET `/v3/sessions/{uuid}`, paginated GET `/v3/sessions` and HTML `/reports/{uuid}` (`views.py:44-80`, `pilot.py:10-22`, `validator_server/urls.py:7-14`). The browser template embeds allowlisted public JSON using Django `json_script` (`templates/validator/report.html:26`); `static/validator/pilot.js:189-260` renders text safely and refreshes the same session ID. No HTTP route for private `export_report` or process review was found. The public interface exposes high-level rights/coverage and known reference file *keys*, not raw process PID, path, basename, private hash, raw Security rows, bearer token or publisher identity.

8. **Scanner's correct link and local history.** `Scanner/src/app/validator_reports.py:51-63,176-252` builds v3 `/reports/{sessionId}` URLs and **only exposes/saves a v3 link after ACK with `reportAvailable=true`**. Before that it displays the active attempt without a clickable link. It handles `previous_session_id` and transport `finish_unconfirmed`, and keeps at most 100 local history entries. `:110-123,254-294` binds a recording only after matching source process identity and bracketing timing/stage samples, **not seed alone**. `:296-371` persists links/status metadata, never write tokens or evidence. `src/ui/validator.py:249-267` rechecks the currently rendered link before opening/copying; `src/ui/validator_reports.py:54-68,114-159` marks interrupted/unconfirmed coverage conservatively. A saved link is not a proof that the *final* ACK arrived; it may remain stored after the server's 90-day retention expires and then legitimately open a 404 page.

## 4. Process catalogue: what is and is not a finding

**Data semantics:**
- **ETW Requested** = an observed process-open request and requested mask, plus a return status. It is **not** proof of permission use, memory reading or game modification. The request's success/failure must be respected.
- **Census Granted** = handle snapshot with effective rights at sampling, not proof they were exercised before/after that poll.
- **Security 4663 Used** = a logged access-right use under the audit's source/target/lifetime limitations; it is not proof of modified game bytes or an unquestionable single target process instance. `Server/sessions/evidence.py:103-139` enforces correlations to accepted prior successful ETW opens, matching source PID+creation time and requested right, with sampled Census target corroboration where present.
- **v4 policy:** `classification.py:453-465` converts v1–v3 uncatalogued Requested/Granted “suspicious” classifications to **neutral private `unclassified`**, removes capability-only findings and preserves real environment/files findings. Historical v1–v3 reports continue using their pinned original rules (`:559-581`); `test_assessment_v4.py:132-141` makes that explicit.

**Narrow verification:** `Server/sessions/rule_data/catalogue-{1,2,3,4}.json` and `registry-{1,2,3,4,5}.json` are versioned datasets registered by `sessions/rules.py:5-27`. `classification.py:123-160,223-266` requires corroborated lifetime metadata and a *specific* approved exact binary SHA or verified publisher signing-key/product/original-name identity, basename, signer, source type, exact right-mask where required and applicable Windows service. Name, PID or signature alone do **not** automatically qualify an executable or new access mask. Current catalogue v4 contains narrowly approved Chrome/Explorer/Defender publisher profiles; README documents scope (`Server/README.md:62-87`). A new catalogue version must be published deliberately; retained existing versions are needed for old reports and active sessions. No automatic whitelisting was found.

**Private operator triage:** `Server/sessions/management/commands/review_processes.py:13-112` scans up to 500 recent **closed, public-available** sessions, skips evidence >2 MiB, considers current catalogue only for private review, groups neutral candidates by executable/signature/image-or-publisher/source/mask/service, counts distinct sessions and writes to operator stdout. It does not change the pinned public result or approve a profile. No public HTTP route exists; `sessions/tests/test_delivery.py:139-225` covers privacy, grouping and non-retroactive review. **Expected limitations:** sessions shorter than publication threshold without positive environment/file findings are not candidates; rows with unresolved source-owner metadata cannot be promoted to named actionable candidates; archived/expired rows disappear; client-generated metadata remains untrusted.

**Specific source-level triage issue found (small, reproducible with a future source test):** `Validator/direct_open_evidence.py:124-145` retains both `requestedMask` **and** `returnStatus`. `Server/classification.py:202-220,223-266` and `review_processes.py:53-80` include ETW Requested observations **without checking `returnStatus==0`** before creating private `unclassified`/review candidates. By contrast the independent **Used** correlation rejects failed ETW opens (`evidence.py:117-125`, `test_access_correlations.py:116-119`). Thus a denied ETW open may inflate a catalogue review candidate as if effective access were requested successfully; v4 currently makes this **triage-quality**, not an automatic public accusation. **Recommended minimal fix after a pure-source regression:** exclude non-successful ETW Requested rows from operator profile candidate counts (or explicitly label them “failed attempt” in separate private diagnostics) in `review_processes.Command.handle`, ideally through a shared success-filtered private observation helper. Do **not** change the original pinned v1–v3 public assessments retroactively. Verify whether code that labels all requests as “successful opens” elsewhere needs only wording adjustment. No new sensor/dependency required. A good regression has two requests from the same pinned source+mask, one `returnStatus=0`, one nonzero, and asserts only the success contributes to approved-access candidate counts; failure can remain raw private evidence.

## 5. Current normal limits, confirmed properties and open risks

### Confirmed directly by code and source test definitions
- Atomic mutation + last sequence/digest/ACK, exact repeat consistency, concurrent duplicate serialization, rollback-on-exception and conflicts: `Server/sessions/delivery.py:37-142`, `sessions/tests/test_delivery.py:421-529`.
- `reportAvailable` is durable, monotonic; publication threshold excludes recorded all-channel gaps, and short qualified findings can publish during finish: `delivery.py:61-115`, `lifecycle.py:68-80`, `test_delivery.py:630-638`.
- Recorded changes in later file checks do not erase prior mismatch or missing findings; rules remain pinned after later catalogue/release version changes: `classification.py:35-60`; `test_delivery.py:314-403,638-672`.
- Local source sender negotiates v3 features, retains immutable in-flight data across *in-process* HTTP retries, isolates overlapping `localRunId` generations, and keeps private evidence out of Scanner history: `transport.py:162-200,477-601`; `controller.py:145-205`; `Scanner/src/app/validator_reports.py:176-252`.
- Public allowlist/private export split: `reports.py:103-170`, `views.py:44-80`, `pilot.py:10-22`, `templates/validator/report.html:26` and browser `pilot.js`.

### Explicit, normal limitations (not defects on their own)
- Client/network data are **not cryptographic attestation**: a client can lie or omit locally collected events; server schema checks consistency and signed/versioned references, **not** trusted execution.
- Worker IPC credit, RAM buffering, bounded network shutdown and terminal diagnostic drop are **not exactly-once crash-durable delivery**. `transport.py:672-691` tracks `finish_unconfirmed` and discarded queued bytes after bounded close; there is no persistent sender journal.
- Offline endpoint/no valid HTTPS endpoint means no server enrollment/ACK and no public link. `transport.py:112-123,173-199`; UI may show local activity only. A network stall can cause stale then 900-second server timeout and a later explicitly partial replacement, not a green merged attempt.
- Short provisional reports are intentionally not public or in Scanner saved history; their evidence is discarded upon closure and the final ACK is retained only for 900 seconds (`lifecycle.py:18-26`).
- Windows 4663 row cap, query truncation, loss markers, audit policy changes, missed attachment and unknown drift block favorable conclusions. An independently evidenced file/mod finding still survives such gaps.
- `imageLoads` finish aggregates are private diagnostics and do not **on their own** establish a plugin loaded into the exact target game at run time.
- Old pinned assessment versions remain historically meaningful, even if v4's neutral capability policy differs. Do **not** bulk-reclassify historical reports.

## 6. Minimal recommendations and handoffs

**Priority A — Validate before changing code:** Instrument the existing session IDs and acknowledge/projection chain on one controlled local run. Protect server secrets and token fields; use the existing `TransportManager.snapshot` (`transport.py:634-660`), Controller snapshot and Django public projection plus operator-only export, never add a new anti-cheat sensor. The purpose is to distinguish *collected*, *queued*, *sent*, *accepted*, *published*, and *finish acknowledged* instead of interpreting a Scanner link as a finish-ACK guarantee. Missing hop → flag `NOT TESTED` or `unconfirmed`, not clean.

**Priority B — Fix the one narrow review-semantic issue:** Test and filter unsuccessful `returnStatus` in private Requested ETW catalogue candidate construction; consider marking failed attempted opens explicitly in private diagnostics. Do not alter historical v1–v3 assessment; no new protocol fields or dependencies.

**Priority C — Accept RAM loss instead of promising impossible recovery:** For user shutdown or process crash with `finish_unconfirmed` / `discarded_on_close`, keep the public classification inconclusive, and make this state clearly visible in Scanner history. If product policy later demands recovery *after client restart*, it would require a separately approved encrypted local spool and credential/retention/threat review; **not recommended as an implicit minimal change**. Current explicit bounded shutdown is a legitimate design trade-off.

**Do not relax the v4 gates** for the saved 17 Nov audit. Calibrate missing-window tolerances only after independent controlled injected failures, preserve boundary guard and Security integrity gates, version the policy. An 85% nominal ETW window cannot be a blanket favorable verdict.

**Integration with concurrent tasks:** 01 supplies trusted wall-clock/QPC and Security time-boundary correctness; 02 supplies 4663 query completeness/row-limit, actor attribution, restoration and diagnostics; 03 owns policy/SACL audit recovery, including interrupted/restarted worker; 04 owns worker IPC ACK/deferred old-run ID, bound close, GUI lifecycle; 05 owns known start/end and one `localRunId` across stage transitions; 06 owns actual poll gaps, ETW/census/image event loss and file/env finding coverage. Task 07 consumes their outcomes at the wire → server decision boundary and **does not** modify their source.
