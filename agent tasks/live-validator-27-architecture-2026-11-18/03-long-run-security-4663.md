## Что сравнить

1. Раздели **четыре** ограничения: 24 удержанных detail rows на группу; 2048 возвращённых записей; 0,8 секунды финального `EvtQuery/EvtNext`; retention/rollover/clear Windows Security журнала. Для каждого назови данные, которые остаются, которые теряются и точный сигнал partial/unknown. Агрегированные record counts не являются числом операций памяти; 4663 не доказывает изменение байтов игры. Отдельно проверь `readStopReason`, `rowsOmitted`, `journal_gap`, `policy_changed`, `clock_changed`, `query_limit`, restoration и wire summary.
2. Сравни три альтернативы без выбора заранее: **A** — оставить end-only, на основе измерений ограниченно увеличить budget; **B** — периодические перекрывающиеся bounded запросы; **C** — настоящий checkpoint с `EventRecordID + log creation epoch/generation`. Для каждой дай максимальное время привилегированного чтения, число запросов, CPU/IO и RAM upper bounds из исходников/сохранённых метрик или пометь `NOT OBSERVED`, стоимость реализации/поддержки, вероятность нового false-clean и объясни, какой из четырёх bottlenecks она **не** устраняет. Не называй фиксированные 5 минут безопасной частотой без скорости журнала и retention evidence.
3. Для B/C проверь инварианты cursor: поколение журнала и oldest boundary, duplicate на overlap, возрастающий watermark только после полного принятого batch, пропуск между batches, clear/recreate, wrap, policy events 1102/4719, late delivery и UTC/QPC drift. При дырке счёт и качество должны явно оставаться partial/unknown; нельзя дополнить неизвестные записи нулями. Проанализируй, возможно ли сохранить bounded aggregate и ограниченный набор details без изменения pinned assessment; отдельно обозначь будущую версионированную policy-дискуссию, если понадобилось бы смягчать `result_limit`.
4. Проследи ownership SACL/recovery: установка до нужной границы, внешнее изменение политики, normal finish, cancel, worker death, old/new run overlap, старый frozen finalizer и новый audit, закрытие при ошибке; ни один checkpoint не должен перехватить restoration чужого рана. Оцени final tail от последнего успешного watermark до подтверждённого конца, `DELIVERY_GRACE` и отсутствие доказательства после неизвестной границы. Конец должен быть immutable для wire/ACK, а failed query не должен давать clean.
5. Поищи только **уже сохранённые** Security/journal/ресурсные traces в `F:/Python/BonkScanner/agent tasks/validator-stabilization-2026-11-17/acceptance/`, `F:/Python/BonkScanner/.local/validator-start-trace/` и `F:/Python/BonkScanner/docs/validator/experiments/`. Укажи длительность, объём, версию и реальные read diagnostics каждого наблюдения. Короткие owned-process tests и 8/8 controlled source matches не измеряют десять часов, чужие машины или абсолютную целевую корреляцию.
