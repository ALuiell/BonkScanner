## Исследовательские вопросы и инварианты

1. Раздели каждое pre-run утверждение на четыре состояния: `observed + run-bound`, `observed but unassigned`, `present in Security journal but outside current query` и `never observed / not evidenced`. Для ETW, стартового Census, ImageLoad, SACL/4663 и file/environment snapshots укажи реальные точки запуска, буферизации, отбора и потери. Отдели время события от времени доставки и время первого `healthy` от фактической активации.
2. Построй временную шкалу из сохранённых трасс: game process PID+FILETIME, attach, ETW start/first healthy, SACL ready/armed, свежие sensor samples, candidate, `run_start`, `begin_run`, первый bound span, финализация. Для каждого предполагаемого переноса события назови исходный timestamp/QPC uncertainty, UTC/QPC bracket и точный допустимый интервал. Если текущий лог не даёт такой цепочки, статус — `NOT OBSERVED`.
3. Проверь контрпримеры: два процесса MegaBonk с одинаковым путём; повторное использование PID и handle; новый ран во время старого finalizer; быстрые рестарты внутри физического sample gap >500 ms; поздний ETW callback; смена времени Windows; неготовый ETW; game/menu с устаревшими флагами. Ни seed, ни player pointer, ни одна menuMusic проба, ни Scanner OFF/SEARCHING/FOUND не становятся доверенной границей. Старый и новый `localRunId` не должны смешиваться.
4. Сравни ровно три исхода: no-change с честным `0→0` marker; узкую привязку **уже наблюдённых** событий при доказуемой границе; ограниченный pre-run ring, только если он даёт дополнительную доказуемую пользу. Для ring рассчитай верхнюю границу памяти, lifetime, eviction, дедупликацию и явное lost/unknown состояние по существующим размерам и частотам; не предлагай тяжёлую глобальную телеметрию в меню без измеренного выигрыша. Не подменяй run detector новой FSM.
5. Сверь ограничения `F:/Python/BonkScanner/docs/updates/functional_updates.md`, D2/v5, версионированный `F:/Python/BonkScanner_validator_server/sessions/assessment_quality.py` и v3 contract. Раздели «известен переход игры» и «наблюдался весь процессный доступ с начала». Сохранение предыдущих findings/unknown gaps обязательно. Никакая локальная привязка не является remote attestation на управляемом клиенте.
